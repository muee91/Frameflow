# Frameflow · 映序

**先同步并交付，让剪辑先开始；素材理解随后在后台完成。**

Frameflow 面向短剧等多机位拍摄：把每个新项目都要临时搭建的同步、场记和素材查询工具，变成一个可反复使用的工作流程。它是全新产品，不继承 MirrorOrder 的工作台、模块组织或旧产品计划。

> 当前是第一项工程实现：可观察的本机同步任务与核对基础。还不是可直接用于生产交付的完整第一阶段产品。没有真实剧组素材、目标 NLE 原生导入验收记录。具体完成度和验收结果只在 [当前任务](docs/TASKS.md) 维护。

## 从哪里开始

界面只有一条主流程：

1. **选择素材**：创建项目，为机位和独立录音分别选择目录，子目录递归识别。
2. **同步**：显示真实阶段、文件、计数、心跳、最后进展和最近活动；可取消、查看原因和重试。
3. **播放核对**：查看同步组，在公共时间轴播放原始视频和独立录音，人工调整起点、确认或排除。
4. **交付**：导出不含本机路径的同步关系清单；生成实验性 FCPXML 工程候选，继续执行目标软件验收。

未匹配素材保留在待处理列表。引擎评分不是正确概率；时间码、连续录制元数据、波形或人工修正各自记录为证据。每个候选都要核对，不自动变成“正确同步”。

## 产品范围

### 第一阶段：同步并交付

必须覆盖整体错位、局部错位、时钟漂移、无时间码、重复对白和独立录音。最终需要两种独立验收的成果：

- **完整多轨同步母版**：保留完整视频、独立录音及所有声道、停机间隙和来源关系。
- **原生多机位素材或工程**：剪辑师能在目标软件中切换机位，继续编辑、保存、重开和重新链接。

目标是 DaVinci Resolve、Premiere Pro、Final Cut Pro 和国内剪映专业版，按实际 Windows/macOS、软件版本和安装来源分别验证。XML 能解析或能导入，不代表原生多机位结构正确。Final Cut Pro 仅适用于 macOS。

### 第二阶段：后台理解素材

交付后异步生成按真实拍摄顺序组织的交互电子场记，结合实际对白、画面、剧本与其他证据识别场次/Take，保留临场发挥，关联演员、角色、镜头类型和内容。支持快速补充特写、OS、临时补拍、空镜及未识别素材，并按拍摄顺序、剧本顺序、演员、对白和语义检索。手写场记只作可选证据。

AI Provider 可本地或第三方、可替换、可追踪，失败不能阻塞或改写第一阶段交付。本轮没有加入模型控制台或假分析。

### 第三阶段：多人使用

围绕按集分工、偶尔接力与共同工作，共享素材身份、同步关系、场记、剧本关联和人工修订。每台电脑独立绑定原始素材路径；音乐、音效是单独的剪辑素材来源。后续先评估 Resolve 原生协作；当前不开发团队权限系统或完整 NLE。

## 运行开发版

需要 Python 3.11+、本机 FFmpeg/ffprobe，以及单独安装的 [Align **v0.3.3**](https://github.com/FedyaLight/align/releases/tag/v0.3.3) CLI。初版锁定已检查的引擎协议，不接受未经验证的其他版本。

macOS / Linux：

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[test]'
frameflow doctor
frameflow
```

Windows PowerShell：

```powershell
py -3 -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -e ".[test]"
frameflow doctor
frameflow
```

将 `align-cli`（Windows 为 `align-cli.exe`）及 FFmpeg/ffprobe 加入 PATH。也可以通过 `FRAMEFLOW_ALIGN` 或 `frameflow --align <本机CLI路径>` 指定引擎。安装器、签名、系统兼容性按上游发布说明处理；Frameflow 不自动下载和执行引擎。

运行后会打开本机浏览器，服务只绑定 `127.0.0.1`。启动链接包含本机会话凭证，不要分享；打开后凭证从地址栏清除。所有媒体处理都在本机。运行数据默认写入用户应用数据目录，可用 `--workspace <目录>` 指定，不应放进 Git 仓库。

仅需诊断依赖时运行 `frameflow doctor`。缺少引擎或媒体工具会明确报告，不回退到模拟同步。

### 当前使用边界

- 目录分组识别机位，名称可编辑；没有声称已完成所有摄影机元数据自动判别。
- 播放使用浏览器真实媒体解码。专业编码代理、逐帧精确播放器、波形视图尚未完成；不支持的编码会报告播放错误。
- 漂移映射保留并展示；分段非线性映射不能被单一起点替代。尚未完成漂移纠正副本和对应交付验证，所以有漂移的 FCPXML 导出被拦截。
- 只允许全部素材已确认或明确排除后交付。多组之间没有共同时间原点时，不擅自把它们拼成一个工程。
- FCPXML 候选含单个同步组的多轨序列和 `multicam/mc-angle/mc-clip` 结构；尚未在 Final Cut 中验证原生对象是否正确。其他目标的正式交付适配仍在验收清单中。
- 本轮有稳定内容身份和本机绑定分层，没有完整的跨电脑导入/重链 UI、多人同步或 AI 场记。

### Resolve 21.1 本机验收桥接（实验）

先从同一已核对修订导出同步清单和 FCPXML 候选。在 Resolve 中保存并关闭现有工程，返回项目管理器，再用其自带的 Python 运行：

```bash
"$RESOLVE_PYTHON" tools/import_resolve.py \
  --manifest /path/to/frameflow-sync-manifest.json \
  --fcpxml /path/to/frameflow-experimental.fcpxml \
  --name Frameflow验收
```

`RESOLVE_PYTHON` 指向目标安装自带的 `ResolvePython`。桥接先逐字节核对 FCPXML 本机媒体与清单内容身份，在**全新项目**中导入普通多轨母版，再通过官方 `CreateMulticamClip`、同步参考入点和 `useFullClipExtents` 建立原生对象及独立验收时间线；不再次自动同步，不覆盖现有工程，不修改原片或自动改变脚本权限。

当前入口仅针对 Resolve 21.1、相同帧率、单组恒定偏移、有共同重叠区间、每份素材单声道或立体声。缺少证据、分段/漂移、未核对素材及其它声道布局会阻断。仍须在目标软件核对完整范围和音轨、切换角度、单路监听、保存重开及重链；导入脚本始终保留 `nle_import_verified=false`，实际验收只记录在当前任务清单。

## 开发与验证

```bash
python -m unittest discover -s tests -v
node --check src/frameflow/static/app.js
```

完整真实引擎测试需要设置 `FRAMEFLOW_TEST_ALIGN`，然后运行同一测试命令。没有设置时测试明确 skip，不能据此宣称真实引擎通过。测试只生成合成音视频到临时目录，不使用或提交真实拍摄素材。浏览器验收脚本和合成素材生成器位于 `tools/`，具体命令及证据见当前任务清单。
